    Roadmap

    中文

    The AArch64, ARM32/A32 and RV64 scalar function-protection baselines, dynamic operand codec, CFG-aware bytecode, sibling multi-VM, real-ELF behavior suites and large-placement stress tests are implemented. The next priorities are intentionally concise.

    Release readiness

    • publish GPL-3.0-only versioned releases using the documented signed-tag/checksum policy;
    • add reproducible-build evidence and CI across supported toolchains;
    • stabilize machine-readable CLI schemas and diagnostic error categories;
    • add packaged-tool smoke tests and compatibility fixtures for multiple compiler versions.
    • consider native Windows/macOS host ports only when demand justifies maintaining ELF and target-tool compatibility layers; WSL2/container workflows are the supported baseline.

    Correctness and platform breadth

    • broaden the implemented AArch64 fixed-width Advanced SIMD subset only when new forms have decoder, typed-lane, native runtime and QEMU ABI coverage; keep SVE/SME and RVV separate future designs;
    • extend remaining uncommon atomics, relocations and compiler-specific scalar forms;
    • strengthen shared-object, TLS, exception/unwind and very-large-application qualification;
    • broaden ARM32 compiler-corpus qualification while keeping Thumb/VFP/NEON explicit opt-in work.

    Quality and analysis resistance

    • initial CFG dominator, natural-loop and multi-class liveness analysis now drives seeded sibling ownership and live-state bridge metadata; the host sibling interpreter now executes deterministic reversible register/flag/vector/SP representation transforms at live-state boundaries, but native runtime bridge integration remains future work;
    • scripts/reference_devirtualizer.py now reverses runtime bytecode whitening and operand encoding on AArch64, ARM32 and RV64 without a sidecar, recovering VM instructions and static CFG edges; optional sidecars quantify exact matches. Next recover handler effects and source-level semantic IR, including dynamic call/return edges, and measure the cost across compilers/functions rather than treating byte entropy as protection evidence;
    • integrate the experimental FunctionVmIsa descriptor into a real per-function encoder and runtime grammar before claiming function-specific bytecode formats;
    • a bounded, same-basic-block miner now reports frequent side-effect-free scalar sequences; synthesize profile-specific bytecode superoperators only with generated handlers and differential semantic validation;
    • add more independently structured dispatch/handler families with measured signature reduction;
    • experiment with selective nested protection only if it materially improves attacker workload beyond sibling mode at acceptable cost;
    • improve automated report comparison across releases, compilers and seeds.

    New architectures

    • design an x86-64 frontend/runtime using the common IR, profile, codec, manifest and ELF64 writer contracts;
    • keep ISA semantics and detours target-specific rather than contaminating common bytecode;
    • consider other executable formats only after ELF architecture boundaries remain clean.

    Long-term Android native target

    • treat Android as an NDK .so protection and build-integration project, not as a claim of Java/Kotlin/Dex or whole-APK obfuscation;
    • begin, if approved, with an arm64-v8a compatibility/liftability corpus before writing Android artifacts;
    • require Android ET_DYN relocation/RELRO, 4/16 KiB alignment, JNI, Gradle, APK/AAB and signing-order gates before declaring support;
    • see the research-only Android native protection vision.

    Roadmap items are not support promises. A feature becomes supported only after host semantics, target-runtime behavior, malformed-input handling and release documentation all pass together.
